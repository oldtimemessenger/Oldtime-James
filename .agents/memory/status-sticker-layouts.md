name: Status stickers and picture layouts
description: User-requested Status participation labels, private question answers, editable titles and independently sized collage elements.
---

Status supports independently draggable and pinch-resizable media, stickers and additional pictures, including picture layouts on a plain background. Every interactive sticker has an optional editable title.

**Why:** the user explicitly requested full-screen portrait pictures, hand sizing, movable stickers and an Overlay button for their own picture layouts.

**How to apply:** preserve the same composed appearance in preview and exported photo/video; editing one element must not move the others.

Questions defaults to editable “Ask me anything,” never “Ask Old Time.” Only the owner can read submitted questions. The owner can choose to answer in a new Status with a camera shot, media or background; do not publish the asker's identity by default.

**Why:** the user specified private owner-only questions and public Status answers.

**How to apply:** keep unanswered question bodies out of public story/reply payloads; retain the original question when sharing an explicit answer.

Shared answers should extend the original Questions artwork, not replace it with a generic card. Owners can reply in Status using a photo/camera background or canvas and text. Notify the owner when asked and notify the asker after a published answer.

**Why:** the user explicitly requested the expanded original field, media/canvas responses, and notifications in both directions.

**How to apply:** keep asker identity out of public answer compositions and question bodies out of notification previews; do not expose an answer's media if its audience excludes the asker.

Trendsetters and Hey World primary participation buttons say “Join”; “Add your own” remains valid secondary wording, never “Add Yours.” Preserve the uploaded original artwork with transparent exteriors for every user, including participants. Keep optional titles editable. This does not reinstate the removed Get On Board feature.

**Why:** the user explicitly required the original artwork for everyone joining, with a tappable Join action.

**How to apply:** keep joins database-driven and visibility-checked; support a closable, swipeable picker and participant list without invented participants.
