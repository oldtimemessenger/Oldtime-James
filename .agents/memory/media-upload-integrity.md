---
name: Media upload integrity
description: Keep resumable upload reservation, digest verification, and fixed-ID retry behavior consistent.
---

**Rule:** A zero SHA-256 value is only a reservation placeholder while new media bytes and the local digest are processed in parallel. Finalize the asset with the real digest only after verifying the stored bytes. Fixed media IDs must reserve against the real digest so retries cannot silently reuse different content. Resumable upload URLs must stay on the browser's origin: return API-relative routes and resolve them client-side against `location.origin`. Bound every browser-side decode, compression, hashing, reservation, transfer, and confirmation step; show which step is running and retain the editor when a step fails.

**Why:** The previous flow stored the zero placeholder and compared it directly with the actual digest, rejecting a completed upload during confirmation. A retry with a stable ID also needs to replace a stale placeholder session once the real digest is known. A reverse proxy can rewrite the API request host to an internal service address, so absolute upload URLs can work in direct worker tests yet point a phone browser at inaccessible localhost. A reported publish spinner had no matching Cloudflare upload reservation, showing that photo/video preparation can stall before any cloud request; signing a selected sound URL also happens before the media reservation and must have a timeout. Safari may return PNG when WebP is requested, so thumbnail encoders must validate the actual MIME and try another supported format. Isolated Worker upload tests do not prove the Pages-to-Worker binding works. Browser encoding must preserve the original audio track without playing it through the speakers. For isolated upload tests, delete the post, then its video, then the thumbnail, and only then the test user; otherwise reference guards or cascades can leave R2 objects behind.

**How to apply:** When changing media upload sequencing, reservation, confirmation, or retries, test placeholder confirmation and fixed-ID recovery through the app’s `/api` proxy with the local R2-backed worker. Assert that the browser-facing endpoint and TUS `Location` remain same-origin paths. Exercise the full post flow with selected sound through the Pages-to-Worker binding, validate thumbnail format fallback in a Safari-like browser, and ensure sound URL signing, video encoding, and transfer each report a bounded, actionable error instead of leaving an indefinite spinner. Verify the original audio is retained without playing it through the speakers.
